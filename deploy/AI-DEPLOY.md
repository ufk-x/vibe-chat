# 给 AI 的 Vibe Chat 部署任务

把下面这段交给有终端权限的 AI。只需要提供自己的域名、SSH 别名或主机地址，以及是否启用语音转写。SSH 私钥和模型 API Key 通过本机或服务器上的私有文件使用。

```text
请从当前 GitHub 仓库部署一套独立的 Vibe Chat，并实际构建、发布和验证 Android APK。先阅读 README.md、deploy/README.md、deploy/ASR.md 和部署脚本。

沿用原项目已使用的平台与链路：阿里云轻量应用服务器，中国香港，Ubuntu 24.04。原实例是 2 vCPU、2 GiB RAM 和 40 GiB 磁盘。优先复用我已有的独立 Ubuntu 主机。需要购买时，选好地区、系统和规格，展示实际价格、续费和流量，停在付款前由我处理。通过控制台绑定本机生成的 SSH 公钥并确认连接。云防火墙开放 80/443，22 限我的部署 IP。8080 保持本机监听。

用我自己的子域名指向主机 IP。没有域名时，可先用 sslip.io 生成测试地址，验证从我的网络可访问。按 deploy/README.md 的命令上传 server/ 和 deploy/，运行 install.sh，验证 systemd、Caddy 自动 HTTPS、备份定时器和 /health。安装脚本适用于专用服务器。如果目标主机已运行其他网站，先读配置并合并站点。

在我的电脑准备 JDK 17、SDK Platform 35、Build-Tools 35.0.0 和 Python。设置 VIBE_ORIGIN 为我自己的 HTTPS 域名。首次构建建立只由我保管的签名密钥，后续沿用。运行 scripts/build.py，然后执行 deploy/release.py prepare 和 publish。查验客户端包内域名、版本和证书，检查公网清单的 SHA-256 与下载包一致。给我首页、APK 和更新清单链接。

先把基础聊天跑通。如果我选择转写，再开通阿里云百炼华北 2（北京），使用 qwen3-asr-flash。用我自己的工作空间 ID 和 API Key 配置服务器 /etc/vibe-chat/asr.env。购买、充值、登录和保存只显示一次的密钥时让我在官方网站或终端操作。检查当前计费并设置音频用量上限，关闭自动充值。配置后重启服务，实际发一段同意用于测试的人声，验证语音先到、文字后来。

用临时测试账号验证注册、好友二维码、文字和语音、悬浮录音。用同签名、较低 versionCode 的预览 APK 对较高版本做在线安装验证。如果现在没有两台可用 Android 设备，先完成服务端与 APK 自动检查，告诉我具体哪些真机行为需要我验证。最后列出域名、版本、服务状态、备份位置和验证结果，以及后续发布时需要保留的签名密钥位置。只在我自己的云账号和主机上操作，不使用原作者的服务器、账单或凭据。
```

阿里云入口及完整命令见 [从零部署](README.md)。
